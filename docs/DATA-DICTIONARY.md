# 访视与冻结定义

样例均为虚构编号，无身份信息。受试者入组日期由subjects表唯一确定，记录中的入组基准必须完全一致。采样日期和入组日期均转为Asia/Shanghai日历日期，差值为访视日；时刻先统一UTC。
方案选择按当前受试者assignment和该次发生时刻查半开生效窗，匹配必须唯一，不能使用全局最新方案。v1访视V1=[5,10)、V2=[12,17)；v2为[6,11)、[13,18)。受试者00001于10月10日转v2，其他受试者仍用v1。
PRIMARY计入访视完成，RETEST只替代该次测量值。首次记录必须唯一且在访视窗内。缺首次访视、重复首次和窗外访视均阻断，复检不能填补漏访或消除原偏离。
复检须引用同受试者同访视的PRIMARY，晚于原采样且不超过72小时，版本必须更高。同最高版本复检冲突时保留原结果并阻断。所有检验值以mg/dL输出，g/L乘100。
锁库须所有规定访视完成，无偏离、复检问题和隔离行。冻结包包含每条选定结果、原始行号、方案版本与访视窗。此工具只验证试验数据完整性，不做诊断判断或生产锁库。

## 冻结凭证

凭证编号 `seal` = SHA-256(规范 JSON)，输入只含封存边界：`format`、`rule_version`、`source_sha256`（导入原字节）、`context_sha256`（方案、入组基准、访视窗、单位等上下文）、`source_rows_sha256`（全部输入行台账）、`visits`（每个受试者每次访视的采信结果、责任行号与原始单元格、方案版本、访视窗、访视日、窗内判定、阻断原因）、`deviations`、`retest_issues`、`quarantine`、`counts`、`balance`。

不进入封存边界：生成时刻、耗时、来源别名 dataset、批次 run_id 标签、复核版本 revision、复核状态 status、页面或文件的展示顺序。因此同一业务内容重新生成、重新下载或换展示顺序，`seal` 不变。

原始行台账保留每条输入行：`data` 采信、`duplicate` 同值重复、`rejected` 隔离、`repeated_header` 重复表头、`blank` 空行，均带原始行号与单元格原值。责任行以 `primary`（首次记录）与 `selected`（采信复检）两种角色记录行号和原始单元格。

`verify.py` 只用包内 `source.csv` 与 `evidence.json` 复算：行台账完整、责任行归属与内容、方案生效窗唯一匹配、访视半开窗与访视日、原值/单位换算后的检验值。任一不符即阻断；与当前批次或另一份凭证比对时输出具体受试者、访视与变化字段。
